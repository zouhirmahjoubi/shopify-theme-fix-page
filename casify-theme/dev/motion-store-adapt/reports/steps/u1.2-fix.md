# u1.2-fix: reduced motion through gsap.matchMedia (cv-pdp-carousel)

Status: done. Defect 1 fixed and re-checked live.

## Root cause
`cvcrInit` read `reduceQuery.matches` once at init (`const reduced`, `const motion`), built the
entrance tweens in a plain `gsap.context` and started the ride only `if (!reduced)`. Nothing
listened for a change, so a shopper switching on Reduce Motion with the page open kept the
auto-running 3D ride, its 8 ScrollTriggers and the pause control until reload.

## Change (assets/cv-pdp-carousel.js only)
- `motion` is now a `let` that is true only inside
  `gsap.matchMedia().add('(prefers-reduced-motion: no-preference)', ..., root)`.
- That branch runs `entrance()` (the old scroll choreography) and `startRide()`; its cleanup sets
  `motion = false`, calls `stopRide()` (destroys the ride, which restores the static still,
  hides pause and hint) and clears leftover inline `transition: none` on chips and buy rows.
  The context revert undoes the entrance tweens and SplitText.
- `startRide()` tags each async ride with a generation number, so a ride that finishes loading
  after a cleanup destroys itself and never shows the pause control; a new ride inherits the
  pause button's pressed state.
- `_cvcrDestroy` now reverts the matchMedia (replaces `ctx.revert()`), then `stopRide()`.
- The pack "Change" scroll reads `reduceQuery.matches` live.

## Re-check (Playwright via the queue, 768x1000, harness/u1.2/pdp.html)
Probe: scratchpad u1.2-fix/probe.py; results harness/u1.2/fix/probe.json; raw output
scratchpad u1.2-fix/probe.out.
- Motion on at load: ScrollTrigger 8, ride canvas 1, stage moving.
- Reduce switched on with the page open: ScrollTrigger 0, canvas 0, stage not moving, stills
  opacity 1 and visible, pause hidden, buy row shown. (Before the fix: still moving, 8, pause.)
- Back to no-preference: ride rebuilt (8, canvas 1, moving).
- Pause, reduce, back on: aria-pressed stays "true"; the new ride takes the paused state.
- Rapid toggles (reduce, on, reduce within 350 ms): ends at 0 ScrollTriggers, no canvas, no
  motion, so a ride that finished loading late destroyed itself.
- Reduce at load: no ride, 0 ScrollTriggers, still shown; turning motion on later starts it.
- Editor, 4 unload/load cycles: unloaded 0 ST, 0 canvas, document 47 / window 22 listeners
  each time; loaded 8 ST, 1 canvas, 48 / 23 each time. Flat, no leak.
- No page errors or console errors.
- Probe step 4 logs a screenshot timeout: the stage sat below the fold (top 3043 at scrollY 0)
  in its pre-entrance state (opacity 0 until 'top 90%'), the same as a first load below the
  fold. Probe artifact, not a defect.
