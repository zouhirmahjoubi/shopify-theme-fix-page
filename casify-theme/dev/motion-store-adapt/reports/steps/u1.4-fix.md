# u1.4-fix: bag page blocking defects (B1 money path, focus after Remove)

File changed: `assets/cv-cart-page.js` only. `sections/cv-cart.liquid` keeps `name="updates[]"`
for the no-JS path (noscript Update button). No locale, template or setting change.

## B1: positional updates[] in the checkout form

Root cause: `updates[]` is matched to cart lines by position. A removed line's input stayed in
the form while `/cart/change.js` was in flight and during the 0.32 s collapse (`inert` does not
exclude it from submission), so checkout could post `['1','3']` against a one-line cart.

Fix (the JS route from the brief, not keyed names, which cannot be checked without a dev store):
- `unname()` drops `name` from every qty input at init and at the end of every swap (both the
  line swap and the empty-state swap). With JS the checkout form posts only the note and
  `checkout`, as it did at HEAD. Without JS the inputs keep `updates[]` and the Update button.
- A removed line's input loses its name and is disabled the moment its swap lands.
- New gap closed: with no names, a stepper change still waiting on its 150 ms debounce would be
  lost if the shopper hit checkout at once. A delegated `submit` listener now sends any pending
  change at once, holds the submit, and resubmits with the checkout button when the queue drains.

Re-check: `scratchpad/u1.4-verify-regression/race_probe.py` (re-run through the queue):
both motion modes post `updates[] = []` before Remove, at the frame the swap lands (server
`[[41002:fixture, 3]]`) and after the collapse. Was `['1','3']` at the swap with motion on.

## Focus dropped to body after Remove

Root cause: the removed line was set `inert` while it held focus, and the empty swap replaced
`page.innerHTML`; nothing received focus.

Fix in `apply()`: if focus is inside a line that is going, the next surviving line's matching
control (Remove, qty input, or the stepper button that was focused) gets focus, else the
previous line's, else the summary heading (`tabindex=-1`). Focus is moved after every line is
swapped so the target is not replaced under it. `focusKey()` now also keeps focus on a surviving
line's Remove across a swap (drawer refresh). On the empty swap, if focus was in the section, the
"Your bag is empty" heading gets focus (`tabindex=-1`); fallback the Start shopping link.

Re-check: `scratchpad/u1.4-fix/focus_probe.py` at 375, cart-model, keyboard Enter on line A's
Remove: focus lands on line B's Remove at the swap frame and after the collapse (both motion
modes); Enter again empties the bag and focus is on the H1 "Your bag is empty"; next Tab is
Start shopping. No page errors. Checkout guard: first submit held (`defaultPrevented`), second
submit after the queue drained went through with the server qty already updated.
