## Changed
- assets/cv-pdp-counter-motion.js (only theme file edited):
  1. Pack click squash now starts on the next frame (requestAnimationFrame). Before, cv-commerce-motion.js
     measured the newly checked box from its MutationObserver in the same tick as the squash, so the
     [data-cvm-pack-highlight] outline took the squashed size and kept it (width +26.9px instead of the
     designed +14, height short).
  2. New settleOutline() on a delegated root `transitionend` (propertyName 'translate', checked .cvc__pack):
     re-places the outline through CasifyMotion.packs(group) with a 0.25 s glide. Cause: the checked box lifts
     5px with a CSS `translate` transition, and GSAP sets `translate: none` inline while it scales the box
     (the click squash and the entry rise), so the outline was measured 5px low after every pick and after
     the entry. Listener is on the section root, not document/window.
  3. handBack() (the 'pdp'/'set' claim hand-back to cv-commerce-motion.js) is idempotent (`handed` flag,
     reset on shopify:section:load), tries at once, then on DOMContentLoaded and window load. The old
     setTimeout(0) path could fire while deferred scripts were still waiting for cv-commerce-motion.js
     (layout/theme.liquid defers both), stranding the claim so cart:added neither flew nor called
     CasifyBag.receive. In headless Chromium the race did not reproduce in the defer mode before the fix.
     It is reasoned from the spec, not observed. The slow mode below proves the new path.
- harness/u1.1/probe-fly.py (new) + probe-fly.json: modes sync (harness as rendered), defer (25 theme
  scripts rewritten to `defer` like the layout), slow (defer + cv-commerce-motion.js answered 1.2 s late).
