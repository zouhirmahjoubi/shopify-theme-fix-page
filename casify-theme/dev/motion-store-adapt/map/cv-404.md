## Store adaptation findings

1. HIGH, link to a page that does not exist / unverified claim. Block `l-1` "How the drop test works" with the drop-shield icon points to `/` (templates/404.json:12); the schema preset ships the same label (sections/cv-404.liquid:91). No drop test is verified (PRODUCT.md "Evidence on Hand": 12 ft drop / MIL-STD-810G not verified; the cv-story drop-test section was removed for that reason, PRODUCT.md:56). Fix: replace `l-1` in templates/404.json with an honest destination using an icon the block's select allows (bag, drop-shield, truck-fast, returns, warranty-seal, quote; sections/cv-404.liquid:72-79), e.g. `{ "icon": "quote", "label": "Questions and answers", "url": "/pages/faq" }` (verify the FAQ page handle first; templates/page.contact.json:23 uses `faqs`) or `{ "icon": "bag", "label": "Every collection", "url": "/collections" }`. Change the preset at sections/cv-404.liquid:91 the same way. Also consider dropping `warranty-seal` from the icon options: no warranty is evidenced.
2. MEDIUM, durability wordplay reads as a product claim. Heading "This one took the drop" and body "The page you were after is gone. The cases, thankfully, are more durable." (templates/404.json:6-7; defaults at sections/cv-404.liquid:18-19, 63-64). Not a measured claim but it implies drop resistance the store has not evidenced. Fix in the shopkeeper voice without performance language, e.g. heading "This shelf is empty", body "The page you were after is not here. The cases are, and so is the search." Update both the template values and the schema defaults/Liquid fallbacks.
3. MEDIUM, the 404 is effectively blank without JavaScript. `.cv-404__inner` carries `data-cv-reveal` (sections/cv-404.liquid:13); theme.css:1073-1074 sets `[data-cv-reveal] { opacity: 0 }` unconditionally and only cv-motion.js adds `.is-revealed`. Crawlers, no-JS visitors, a slow or failed `cv-motion.js`, and a section re-rendered in the theme editor (cv-motion.js has no `shopify:section:load` handler) all see an empty page. Fix (owned file only): remove `data-cv-reveal` from line 13 and drive the entrance with a GSAP `from()` (see opportunities), or add `<noscript><style>.cv-404 [data-cv-reveal]{opacity:1;transform:none}</style></noscript>` inside the section.
4. LOW, search is not scoped to products. The form submits only `q` (sections/cv-404.liquid:21-28) while the placeholder says "Search for your phone model". Add `<input type="hidden" name="type" value="product">` and `<input type="hidden" name="options[prefix]" value="last">` so "iPhone 17" returns cases, not blog posts.
5. LOW, hardcoded English: "Search" button text and aria-label (sections/cv-404.liquid:25-26). Move to locales later.
6. LOW, comment header still says "Chrismass design system" (sections/cv-404.liquid:2) and uses an em dash; not shopper-facing, but rename to Casify for clarity.
7. No prices, currencies, other brands or candy-as-product copy.

## Motion inventory

- `data-cv-reveal` on `.cv-404__inner` (line 13): opacity/translate entrance via IntersectionObserver in cv-motion.js:132-145.
- `data-cv-split` on the h1 (line 18): word stagger (cv-motion.js:66-84; CSS theme.css:1086-1092). Words are visible without JS because `.cv-split` is only added by JS.
- `data-cv-stagger` on `.cv-404__links` (line 54): sets `--cv-i` on the links, but the links themselves are not reveal targets, so the stagger index has no visible effect beyond the parent reveal.
- `cv-icon ... animate: true` on the shield (line 15): CSS keyframes `.cv-ico--anim` plus `.cv-404__code em { animation: cv-float 7s infinite }` (theme.css:2582). Infinite ambient loop; does not pause offscreen or when the tab is hidden (DESIGN.md Motion asks long-running ambient motion to pause offscreen).
- Hover lift on `.cv-404__link` (theme.css:2597) and the global `button[type="submit"]:hover` lift.
- Reduced motion: theme.css:3232 forces `[data-cv-reveal]` visible, 3241 split words visible, 3242 stops the float, 3249 removes link hover transform. Good.
- No-JS: whole block invisible (finding 3).
- Theme editor: no section load/unload handling anywhere for these attributes.
- No section-specific JS, no GSAP use today.

## Risks

- theme.css is shared by every section; implement the no-JS fix inside the section (remove the attribute or add a scoped noscript style) rather than changing the global `[data-cv-reveal]` rule, unless the shared-file owner does a theme-wide `@media (scripting: enabled)` gate.
- The 404 template has no `request.design_mode` exception for non-`/pages/` URLs; a new link to a missing collection would still render. Keep links to `/collections`, `/collections/all`, `/search`, existing pages.
- If a product shelf is added, it must stay empty-state hidden when the collection setting is blank, and must never show a hardcoded price or a guessed phone model.
