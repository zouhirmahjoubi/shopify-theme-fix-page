## R2. Idea: compare_price_fallback as a theme setting (owner of config/settings_schema.json)

- map/cv-pdp-carousel.md finding 2. The buy box's fallback compare-at price is a section setting
  (`sections/cv-product-counter.liquid:883`, stored `""` at `templates/product.json:157`). Liquid in
  `cv-pdp-carousel.liquid` cannot read another section's settings.
- What U1.2 did: the first paint shows a was-price only from the variant's own compare-at price; the script
  applies the buy box fallback (`data-compare-at-fallback`, `assets/cv-pdp-carousel.js:949`) as soon as it runs.
  The section comment now says so. With the stored value `""` today, static, no-JS and JS states agree.
- Gap: if the merchant sets the fallback (PRODUCT.md mentions $59.99), the no-JS carousel would show no
  was-price while the buy box shows one. With JS the two agree.
- Idea (needs the shared schema owner, not U1.2): add `settings.cv_compare_price_fallback` (text, default
  blank, same info text and shop-currency rule) to `config/settings_schema.json`. Then the buy box reads
  `section.settings.compare_price_fallback | default: settings.cv_compare_price_fallback` and the carousel
  reads the theme setting for its first paint. Keep the buy box section setting; the template stores it.
- Only a was-price the case really sold at may go in it (claims rule). No change asked today.
